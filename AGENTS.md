# Development Commands

- Install: `uv sync`. `flodym` (the MFA framework) may be a local editable dependency from `../flodym`.
- Type check: `uv check` (runs `ty`). (it does exist but may not be in your training set)
- Tests: `uv run pytest`.
- Run a model headless (the `ci` layer disables plotting, which would otherwise open a browser):
  `uv run remind-mfa --config default --config ci --model {steel,cement,plastics,all}`
- Run Marimo notebook headlessly:
`uv run marimo export html notebooks/<name>.py -o /tmp/out.html`
- Before completing a change run `uv check` and `uv run pytest`.
- Never run any formatter, linter, or pre-commit unless working on their configuration
(`uvx pre-commit run --all-files`).
- `flodym` API reference: Call `context7` `query-docs` with library ID `/websites/flodym_readthedocs_io_en`, or look at the code in `.venv/lib/python*/site-packages/flodym/`


# Repository structure

- `remind_mfa/cli/`: typer entry point (`remind-mfa`).
- `remind_mfa/common/`: shared model, config, data reader, scenarios, extrapolation, trade, export, visualization.
- `remind_mfa/{steel,cement,plastics}/`: one package per material model.
- `config/*.toml`: run configuration. `config/scenarios/`: scenario parameters
  (see `config/scenarios/README.md`).
- `data_in/dimensions/<model>/`: tracked dimension CSVs. `data_in/parameters/`: gitignored, extracted from
  the madrat archive. `data_in/legacy/`: private git submodule (PIK GitLab) with legacy cs4r parameters.
- `data_out`: run outputs, gitignored.
- `docs/`: mkdocs site. `docs/<model>/config_schema.md`, `docs/<model>/definitions/*`, and
  `docs/<model>/assumptions.md` are generated by the docs export of a model run. Never edit them by hand.
- `scripts/`: one-off utilities (`fetch_from_hpc.py` downloads input archives from the PIK cluster).
- `notebooks/`: marimo notebooks for data analysis
- `tests/`: pytest, mirrors the package layout.

# Input data

- Parameters are `.cs4r` files (CSV with `*`-prefixed header lines) produced by the R package `mrmfa`
  and shipped as `rev<rev>_<regions>_<hash>_mfa.tgz`. The archive is selected by
  `input.input_data_revision` and `input.region_mapping` in the config and extracted into
  `data_in/parameters/` on first run.
- The archive location comes from `input.madrat_output_path` or the `MADRAT_OUTPUTFOLDER` env var.
- Parameter files are prefixed by the first two letters of the model (`st_`, `ce_`, `pl_`).
- Dimension files are mapped by name in `<model>_mappings.py`.

# Conventions

- The different material models are referred to as `models` and not `materials` in the code.
- Target Python 3.12: `X | Y` annotations, PEP 695 `type` aliases and generic syntax (`def f[T](...)`) are desired.
- Use type hints. Currently, `pyproject.toml` disables a number of `ty` rules globally under `[tool.ty.rules]`. Code you add or touch should not need new entries in that ignore list.
- Use descriptive variable names, not single-letter.
- Use google-style docstrings (https://google.github.io/styleguide/pyguide.html).
- Add pytests for critical functionality. Don't add tests for code in notebooks.
- Commits and PR titles use Conventional Commits with types `feat`, `fix`, `docs`, `chore`. Issues are at github.com/pik-piam/industry_issues.
